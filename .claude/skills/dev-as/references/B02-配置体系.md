# B02 · 配置思想（三层生效 + 双信任面）

> 一句话：**env > store > 动态构造**。容器部署把配置当环境（env 注入、改 compose 重启）；本机形态把配置当数据（面板/CLI 改 store）。永远通过 `oidcConfig()` 取生效值，别直读 store 判配置。

## 三层生效（src/runtime/oidc.js `oidcConfig()`）

| 层 | 载体 | 谁写 | 何时生效 |
|---|---|---|---|
| **env** | `NXAS_OIDC_ISSUER / CLIENT_ID / REDIRECT_URI / SCOPES / ALLOWED_EMAILS` | compose / 部署脚本 | 进程启动即覆盖一切 |
| **store** | `~/.nx-as/store.json` 的 `oidc.{issuer,clientId,redirectUri,scopes,sessionSecret,allowedEmails}` | 面板「登录与会话」页 / `nx-as oidc config set` | 立即（env 未设时） |
| **动态构造** | redirectUri 为空时按 `X-Forwarded-Proto + Host [+ /_nxas 前缀]` 现算 | —— | 回环部署免配置（go-ah 白名单对回环端口通配） |

- `allowedEmails`：登录白名单（空 = 放行全部 go-ah 用户；**gost-as 公网部署被 gost-init 强制非空**）。回调处用生效值比对（`runtime/session.js`），env 设了面板改 store 不生效——这是特性不是 bug。
- `sessionSecret`：会话 HMAC 密钥，首用时生成落 store（重启不掉线）；`nx-as auth rotate` 轮换 = 全端下线（无单条吊销，个人工具取舍）。

## 双信任面（正交，别混）

| 面 | 凭据 | 用途 | 落点 |
|---|---|---|---|
| **人 → nx-as** | go-ah SSO 会话 `nxas_s2.*`（7 天，cookie/Bearer 双载体） | 面板/网关/隧道口鉴权 | 浏览器 cookie 或 `~/.nx-as/credentials.json`（0600） |
| **nx-as ↔ pi-web** | `machineSecret`（机机 Basic `pi:<secret>`） | 反代注入上游、rotate-secret 轮换 | store + `/data/gost-auth.env` 同级 |

## 凭据/配置文件全景

```
~/.nx-as/store.json        oidc 配置 + sessionSecret + machineSecret + nginx 托管设置
~/.nx-as/credentials.json  CLI 会话（nx-as login / client login 落盘；0600）
~/.nx-as/client.json       client 域连接：server.api / relay.url / gost.bin / tunnels[]
                            （server.token 字段已废——残留旧值会盖过 credentials 导致 401，清掉）
/data（gost-as 容器卷）     store.json / audit.jsonl / gost-auth.env / http.d/ / nginx-backups/
```

## gost-as compose 必填/常用 env（docker-compose.gost-as.yml 同步维护）

```yaml
NXAS_OIDC_ISSUER: http://<go-ah>          # 必填（gost-init 硬门槛）
NXAS_OIDC_CLIENT_ID: nx-as                # 必填
NXAS_OIDC_ALLOWED_EMAILS: a@b.com         # 必填——不设容器拒绝启动（任何 go-ah 用户都能进的拒绝态）
NXAS_OIDC_REDIRECT_URI: http://<公网>:8090/_nxas/oidc/callback   # 公网部署必填（nginx 不透传真实 Host 时动态构造会算错）
NXAS_BIND_AUDIT_ALLOW: 22,80,...          # 守卫白名单（宿主既有端口，防告警噪音）
NXAS_GOST_INTERNAL_PORT: 18442            # relay 回环口（默认即可）
```

> 教训（真实）：容器 nginx 反代不透传外部 Host → 动态构造出 `127.0.0.1:7801` 的 redirect_uri → 远程用户被回调到自己机器。公网部署**显式设 REDIRECT_URI**。

## client 一致性：probe 四段

`nx-as oidc probe`（零凭据，启动日志自动跑）：discovery 可达且 issuer 逐字一致 / client 已注册（合法 redirect 302）/ 伪造 redirect 被拒 / **生效 redirect_uri 已被 go-ah 接受**。部署漂移在这四段里现形；改公网地址/换端口后先跑它。

## 错误案例（真实）

| 坑 | 后果 | 预防 |
|---|---|---|
| client.json 残留旧 `server.token` | resolveClientToken 优先取它 → 全部 API 401 | `nx-as client config set --server <api>` 清空（写 token:''） |
| 回调白名单读 store 而非生效值 | env 白名单不生效 | 一律走 `oidcConfig()` |
| redirect_uri 动态构造依赖 Host 头 | 经容器 nginx 后算错 | 公网部署显式配 `NXAS_OIDC_REDIRECT_URI` |
